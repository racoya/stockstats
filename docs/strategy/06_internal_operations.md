# Strategy 06: Internal Operations & The Command Center

## 1. The Operational Objective
To architect the proprietary user interface (UI) and heavily fortified REST backend access controls that our internal quantitative team will use to monitor, manage, and analytically audit the autonomous trading engine. 

This is not a retail trading app. It is a bespoke internal Bloomberg Terminal built explicitly for monitoring real-time mathematical expectancy, tracking fractional Kelly deployments, and triggering global Kill Switches during structural market failures.

## 2. User Roles & RBAC Architecture
Because this platform manages proprietary capital, structural application access must be strictly compartmentalized via Role-Based Access Control (RBAC).

*   **Administrator (Founders/Lead Quants):** Unrestricted Read/Write access. The only tier capable of altering raw codebase logic, adjusting the overarching Parametric VaR (Model 12) global limits, and physically triggering or resetting the Master Kill Switches.
*   **Senior Execution Trader (Monitoring):** Read/Write access strictly bounded by mathematical parameters. Can manually intervene in trades, override a False-Positive XGBoost veto (Model 10), and explicitly monitor all active positions. *Cannot* alter the static mathematical Python equations or bypass hard system VaR limits.
*   **Data Analyst (Research):** Read-only access to all databases. Can view immutable `TimescaleDB` historical ticks, backtesting outputs, and live system telemetry to research new structural edges or investigate execution slippage deltas. Cannot physically route capital.

## 3. The Immutable Ledger & Edge Tracking
A critical operational mandate is solving the "Origin" problem: When algorithms and humans interact within the same consolidated portfolio margin balance, we must mathematically separate and track *Human Edge* vs. *Machine Edge*.

*   **The Cryptographic Audit Log:** Every single $1R$ normalized execution—whether generated autonomously by `Algo_Cointegration_BTC` or manually overridden by `Trader_JohnDoe`—must be hashed and appended to an immutable PostgreSQL ledger.
*   **Mandatory Telemetry Tags:** Every execution payload must contain:
    *   `Source_Origin_UUID` (The specific algorithm or human ID)
    *   `Theoretical_E(R)` (The mathematically projected Expectancy at the time of firing)
    *   `Macro_Regime` (The HMM State, Model 03, at the time of firing)
*   **Decoupled PnL Dashboards:** The system must dynamically isolate the System Quality Number (SQN), Win Rate, and realized R-multiples generated by *human manual actions* entirely separately from the *automated systemic actions*. This mathematically proves if human intervention is actively increasing or destroying the system's baseline $E(R)$.

## 4. The Live Navigation UI (The Terminal)
The central operational hub during active continuous trading.

*   **The Telemetry Bar (System Health):** Real-time monitoring of WebSocket ping latency to execution exchanges, remaining API rate limits, PostgreSQL CPU persistence load, and the live realized Slippage Delta (Model 05).
*   **The Global Risk Matrix:** A consolidated view of total nominal portfolio exposure mapped against the dynamic Parametric VaR limit. Displays active Copula dependency heatmaps to visualize real-time systemic crash threats.
*   **The Algorithmic Logging Feed:** A scrolling stream of what the mathematical engines are currently structurally analyzing (e.g., `14:02:01 UTC | BTC_USD | Signal: 2.1 Sigma Deviation | Action: Paused | Reason: OBI Toxicity = -0.85`).
*   **The Master Intervention Interface:** A prominent, heavily authenticated section allowing an Admin to instantly liquidate a specific algorithm's positions to cash, or trigger the Global Halt during unforeseen, non-mathematical Black Swan events (e.g., a total exchange collapse).

### A. The "Poison Seed" (API Key Rotation)
Algorithms have been drained by rogue actors gaining access to "stale" Execution API keys that were never rotated.
*   **The Problem:** An engineer accidental commits a `.env` file containing the physical Trading API keys to a public GitHub repo. The system is instantly compromised.
*   **The Operations Protocol:** The UI Terminal must contain a physical **Key Rotation Vault**. The Operations mandate states that Exchange API keys must be hard-coded with a maximum 30-day expiration window natively on the Exchange (e.g., Binance API management). The terminal will pulse a Critical Alert 48 hours before the keys expire, forcing the Administrator to manually cycle new cryptographic keys into the vault, ensuring a compromised "Poison Seed" can never permanently gut the fund.

## 5. Dynamic Routing & Contextual 404 Security
The system must gracefully handle HTTP navigation errors while maintaining strict systemic security per the authenticated user's RBAC level. This is critical for preventing unprivileged roles from accessing dormant administrative endpoints.

*   **Strict Middleware Interception:** The Node.js/Python backend must enforce rigid JWT token routing. If an Analyst attempts to `POST` to `/api/admin/kill-switch/trigger`, the middleware must reject the request at the network edge before logic execution.
*   **Role-Aware 404/403 Error Pages:** The "Page Not Found" (404) or "Unauthorized" (403) react interfaces will dynamically render distinct recovery paths based on the user's explicit role:
    *   *Administrators:* See a specialized 404 page featuring immediate diagnostic links, server error logs, and user management overrides.
    *   *Execution Traders:* See a 404 page that instantly redirects them safely back to their live active portfolio view or the execution terminal, ensuring they are never lost in the UI during fast-moving, high-volatility markets.
    *   *Analysts:* See a 404 page seamlessly pointing back to the TimescaleDB research querying interfaces and DSR backtesting environments.
*   **The Living Compass:** The 404 page and primary navigational sidebars must be continuously updated in real-time as new modules (e.g., Options pricing overlays) are developed, guaranteeing all users have immediate optical paths back to their authorized execution domains.
